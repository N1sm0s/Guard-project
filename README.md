# IntegrityGuard — нейросетевой контроль целостности пакетно-нейросетевых программ

Программное средство по теме «Разработка модели системы защиты информации, основанной на
проблемно-ориентированной конструкции нейронных сетей, в интересах выявления угроз нарушения
целостности пакетно-нейросетевых программ (ПНП)».

## Запуск

1. Один раз запустите `install.bat` — он создаёт окружение Python, устанавливает библиотеки,
   собирает portable-приложение и создаёт ярлык на рабочем столе (и в каталоге проекта), если
   ярлыков ещё нет. Для установки нужен Python 3.10+.
2. Запускайте `F:\New\integrityguard\dist\IntegrityGuard\IntegrityGuard.exe` или уже имеющийся ярлык.

### Сборка Windows-дистрибутива

`build_exe.bat` пересобирает onedir-дистрибутив в `dist/IntegrityGuard/`.
`create_shortcut.ps1` при первом запуске создаёт ярлыки (на рабочем столе и в каталоге проекта); при
повторных запусках обновляет путь у уже существующих ярлыков. `install.bat` вызывает этот скрипт
автоматически после сборки.
В отличие от исходного режима, сборка хранит настройки, реестр и журналы в
`%LOCALAPPDATA%/IntegrityGuard/data`, чтобы не записывать их в каталог программы.
PyInstaller устанавливается в `.venv` только для сборки и не добавляется в runtime-зависимости.

## Структура проекта

- `integrityguard/` — код приложения и детектора.
- `assets/`, `models/` — ресурсы интерфейса и основная модель.
- `corpus/`, `data/` — обучающий корпус и локальные данные приложения в режиме разработки.
- `docs/`, `tests/`, `tools/` — методика, проверки, диагностика и оценка внешних пакетов.
- `tools/dev/` — вспомогательные точки запуска исходного кода.
- `tools/maintenance/` — утилиты обслуживания и диагностики.
- `tools/legacy/` — устаревшие скрипты; массовая разметка и старое обучение не являются частью рабочего контура.
- `data/legacy/` — сохранённые корневые БД, не используемые приложением.
- `outputs/` — результаты экспериментов, отчёты и скриншоты тестовых прогонов.
- `build/`, `dist/`, `.venv/` — генерируемые файлы сборки и окружение Python.

`run.bat` запускает исходный код для разработки. Для обычного запуска используйте прежний portable EXE.

Рабочий путь использует реальные пакеты. Вручную укажите каталог кнопкой «Обзор…» либо поместите пакет в
`data/incoming`: программа автоматически дождётся завершения копирования, проверит пакет и сохранит событие.
Каталог, выбранный вручную, наблюдается на изменения и перепроверяется автоматически. Генерация и запуск
синтетических демо-пакетов отключены в интерфейсе; синтетические метрики не отображаются как качество модели.
Поставляемый детектор экспериментальный; качество на реальных угрозах не подтверждено.

Автоматический монитор также принимает реальные Python wheel (`*.whl`) в `data/incoming`. Он проверяет ZIP-
структуру, `METADATA`, `RECORD`, SHA-256 состава, зависимости и ограниченный статический набор признаков
исходников; код пакета не устанавливается и не исполняется. Для точного сравнения оператор сначала закрепляет
проверенный wheel как эталон. Совпавший SHA-256 и корректный `RECORD` дают `ALLOW`; новая или изменённая версия
получает `REVIEW` и сохраняется для ручной проверки. ML-оценка для этого формата не выдумывается и остаётся
пустой. Подробности — в [`docs/real-artifact-workflow.md`](docs/real-artifact-workflow.md).

Вкладка «Мониторинг» показывает графики: поток пакетов, поступающих на проверку (по времени и вердиктам),
оценки нарушения, распределение заключений и входящие сетевые пакеты компьютера (нужна библиотека `psutil`,
её ставит `install.bat`).

### Статус сетевого классификатора

Для исследовательского отбора кандидата действует dev-ограничение: верхняя 95% Wilson CI FPR не выше
**0,25% отдельно на каждом целом development-захвате**. Оно применяется только при сравнении/выборе
кандидата и не меняет release gate. Текущий проспективный предел допуска — **≤0,25% upper two-sided 95% Wilson CI FPR**
и **≥80% lower 95% CI recall на каждом независимом test-захвате**. Исторические отчёты сохраняют
фактически применявшиеся при их запуске пределы. При нуле FP требуется минимум 1 533 benign-потока на захват;
при FP нужный объём определяется фактической Wilson CI и может быть больше.

По состоянию на 20.11.2026 release dashboard показывает **4/10 этапов (40%)**. Текущий production-path
кандидат не прошёл source-test: capture 46 не достиг recall CI-L 80%. FPR CI-U capture 47 был 0,1180%, что выше
текущего предела 0,1%; уже использованная оценка в любом случае не считается подтверждением нового проспективного gate. Последний read-only runtime-снимок (12:32:36 UTC) показывает 16 895 связанных с кандидатом полных
потоков, P95 inference 5,369 мс и целостные evidence-цепочки; это не целевой нагрузочный тест. Целевые
incident labels и численная потеря Pktmon-сенсора пока не подтверждены; модель остаётся advisory-only,
автоматическая блокировка выключена. Подробные результаты и ограничения:
[`docs/network-model-release-gate.md`](docs/network-model-release-gate.md).

## Автоматический режим (включён по умолчанию)

- Приложение не генерирует и не проверяет синтетические демо-пакеты. Для рабочих проверок используются только
  пакеты, помещённые пользователем во входящую папку или выбранные вручную.
- Папка `data/incoming` — входящие пакеты. Скопируйте туда каталог пакета: он будет проверен без нажатий и
  переложен в `data/processed/allow`, `review` или `block` (карантин). Некорректный каталог уходит в `error`.
- В эту же папку можно скопировать настоящий `.whl`. Он автоматически проходит статическую проверку и сравнение
  с закреплённым wheel-эталоном. Незнакомый артефакт направляется в `review`; первая встреча не считается доверием.
- Результат проверки и задание на перенос сохраняются до завершения архивации. При временной блокировке файла
  повтор откладывается на 2, 4, 8 и далее до 300 секунд; ожидание сохраняется при перезапуске. Один и тот же
  результат не добавляется повторно в журнал.
- Пакет без зарегистрированного эталона получает статус «сравнение не выполнено», остаётся на проверке и
  записывается в журнал без числового балла. Первая встреча и локальная подпись не считаются доверием.
  Нейросетевое сравнение версий выполняется только после регистрации доверенного эталона на вкладке
  «Эталоны и версии».
- Для зависимостей, явно помеченных `source=pypi`, программа проверяет рекомендации OSV. Отправляются
  только имя и версия публичной зависимости; исходники и веса модели не отправляются. Найденная рекомендация
  требует ручной проверки. Отсутствие совпадения не подтверждает безопасность; источник и полнота запроса
  сохраняются в журнале и PDF.
- Обычный запуск не создаёт демонстрационные пакеты и не запускает синтетическое обучение. Поставляемая модель
  экспериментальная; её качество на реальных пакетах пока не подтверждено.
- Графики, журнал и история обновляются сами. Недостающие небольшие библиотеки доустанавливаются при запуске.
- Отключается галочкой на вкладке «Настройки».

Выбранный пакет проверяется по изменениям метаданных каждые 4 секунды; полная сверка содержимого SHA-256
выполняется при изменении метаданных и не реже одного раза в минуту в фоновом потоке. Если пакет меняется
во время анализа, результат не принимается и каталог проверяется повторно. В CLI-мониторе частота ограничена
диапазоном 2 секунды — 1 час; ошибки попадают в журнал и вызывают повтор с задержкой до 60 секунд. Идентификатор
события зависит от отпечатка пакета, поэтому повтор после перезапуска не создаёт дубль.

### Работа в фоне (значок в трее) и автозапуск

- Закрытие окна (крестик) не завершает программу — она сворачивается в значок в системном трее и
  продолжает проверять входящие пакеты. Через меню значка (правая кнопка мыши) можно открыть окно снова,
  включить/выключить автоматический режим или выйти из программы по-настоящему.
- На вкладке «Настройки» есть галочка «Запускать автоматически при входе в Windows (в трее, без открытия
  окна)». Она добавляет (или убирает) ключ автозапуска в реестре текущего пользователя
  (`HKCU\...\CurrentVersion\Run`) без установки службы и без прав администратора. При входе в Windows
  программа запускается сразу в трее и начинает проверять входящие пакеты без участия пользователя.
- Ручной запуск в трее (минуя автозагрузку): `IntegrityGuard.exe --tray`.

## Что делает программа

Кандидат (новая версия пакета) сравнивается с доверенным эталоном на трёх уровнях целостности.

| Уровень | Что анализируется | Ветвь сети |
|---|---|---|
| Структурный | граф компонентов: зависимости, модули, модель, слои; версии, хеши, источники, «возможности» кода (сеть, запуск процессов, eval, обфускация…), тайпосквоттинг | графовая нейросеть (GNN) |
| Параметрический | портрет каждого слоя: статистика распределения весов, спектр (сингулярные числа), отклонение от эталонного слоя; архитектура кодировщика выбирается автоматически (MLP/CNN/LSTM/Transformer) | автокодировщик весов (WeightAE) |
| Поведенческий | отклик на контрольные входы и обратная реконструкция триггера (поиск минимального возмущения, переводящего входы в один класс) | классификатор аномалий |

Блок объединения выдаёт класс нарушения; дополнительно — оценки по уровням и указание
подозрительного компонента (зависимость, модуль, слой).

### Классы нарушений (9 классов)

| № | Класс | Описание | Уровень целостности |
|---|---|---|---|
| 0 | `clean` | Нарушений нет (легитимное обновление) | — |
| 1 | `dependency` | Компрометация библиотек и компонентов | структурный |
| 2 | `weights` | Подмена или изменение весов модели | параметрический |
| 3 | `backdoor` | Внедрение триггера (бэкдора) | поведенческий |
| 4 | `poison` | Отравление обучающих данных | поведенческий |
| 5 | `label_flip` | Подмена меток | поведенческий |
| 6 | `adversarial` | Состязательные входы / эвазия модели | поведенческий |
| 7 | `extraction` | Несанкционированное извлечение модели | структурный |
| 8 | `availability` | Нарушение доступности (атака типа DoS) | поведенческий |

## Статус реальной оценки

Независимая оценка на реальных пакетах пока не проведена: проверенный размеченный корпус отсутствует.
Встроенный детектор и сохранённые `models/metrics.json` получены на синтетическом корпусе и считаются
экспериментальными; их метрики не являются показателями качества на реальных инцидентах и не используются
как подтверждение безопасности.

### Архитектура WeightAE (авто-выбор кодировщика)

Кодировщик весовых слоёв выбирается автоматически по числу слоёв в модели:

| Число слоёв | Архитектура |
|---|---|
| 1–3 | MLP (полносвязная сеть) |
| 4–8 | CNN (1D дилатированные свёртки) |
| 9–24 | LSTM (двунаправленный, 2 слоя) |
| 25+ | Transformer (само-внимание, 4 головы) |

## Как устроен корпус

Корпус формируется программными сценариями чистых обновлений и изменений моделей. Это синтетический
исследовательский материал, а не набор подтверждённых реальных инцидентов. Разбиение на обучение,
валидацию и тест выполняется по проектам, но такие результаты не доказывают переносимость на реальные
пакеты. `models/detector.pt` остаётся экспериментальной моделью до независимой проверки на достоверно
размеченных реальных данных; подробности — в `docs/methodology.md`.

## Командная строка (для конвейера сборки и поставки)

    python -m integrityguard baseline-wheel --wheel <trusted.whl> --registry registry --source-url <project-url> --provenance-ref <review-reference>
    python -m integrityguard check-wheel --wheel <candidate.whl> --registry registry --report report.pdf
    python -m integrityguard baseline --package <эталон> --control control.npz
    python -m integrityguard check --package <кандидат> --strict       # 0 допуск, 1 блокировка, 2 на проверку
    python -m integrityguard monitor --package <развёрнутый пакет>     # контроль в эксплуатации

`baseline-wheel` должен получать только проверенный оператором реальный артефакт. `source-url` и
`provenance-ref` сохраняются как происхождение, но приложение не подтверждает эти ссылки автоматически.
`check-wheel` не устанавливает пакет; код возврата 0 означает точное совпадение закреплённого wheel, 2 — ручную
проверку. Для незнакомого пакета это не модельный вердикт и не подтверждение безопасности.

Каждая проверка добавляет строку JSON в `registry/events.jsonl` — источник событий для SIEM/SOC.
Одновременно новая SQLite-база `registry/evidence.sqlite` связывает событие с хешем активной
модели, сохраняемыми тензорами признаков и подтверждённой человеком бинарной меткой. Старые
`events.jsonl` и `events.archive.jsonl` при старте идемпотентно импортируются; для исторических
событий, где модель и признаки не записывались, происхождение помечается `legacy_jsonl`, а
отсутствующие доказательства остаются неизвестными. JSONL остаётся совместимым экспортом.

Подтверждение примера из аудита формирует отдельную модель-кандидата в
`data/models/candidates/<candidate_id>/`. В манифесте фиксируются хеш родительской модели,
хеш обучающих данных и обязательный статус `awaiting_independent_evaluation`. Рабочая модель
автоматически не заменяется. Постановка обучения проверяется фоновым таймером каждые 15 минут
и при подтверждении метки; между запусками сохраняется не менее 24 часов. Нужны минимум 20
подтверждённых примеров, из них не менее 5 на каждый бинарный класс. Один запуск ограничен
500 примерами, 3 эпохами и одним CPU-потоком. Это формирует только кандидата. Независимая оценка, вычислимые критерии допуска, повторная проверка перед активацией, резервная копия и восстановление незавершённого выпуска реализованы. Пока нет независимой проверенной реальной выборки, активация модели блокируется; описание формата и ограничений находится в docs/candidate-release.md.

## Формат пакета

    manifest.json   имя, версия, зависимости (имя, версия, sha256, источник, requires, размер)
    manifest.sig    подпись выпуска (HMAC-SHA256 по всем файлам)
    model.pt        веса (state_dict)
    src/*.py        собственные модули
    vendor/<имя>/   код зависимостей (необязательно)

## Ограничения

- Корпус синтетический: небольшие полносвязные сети на модельных задачах и синтетические графы
  зависимостей. На реальных пакетах и моделях показатели не измерялись.
- Поведенческий и параметрический анализ поддерживает модели вида Linear+ReLU, сохранённые как
  state_dict. Для других архитектур нужно дописать функцию прямого прохода.
- Состязательные входы, извлечение модели и нарушение доступности (угрозы 4, 7, 8) — угрозы времени
  выполнения, проверкой артефактов не выявляются напрямую; детектор выявляет косвенные признаки.
- Подпись — симметричный HMAC, это упрощение для прототипа.
- Модель, сохранённая небезопасным pickle, блокируется правилом политики без загрузки файла.
- Ни синтетические показатели, ни GUI-сценарии не считаются измерением качества на реальных инцидентах.
  Для независимой оценки нужен подтверждённый корпус реальных пакетов с проверяемым происхождением
  разметки и разделением данных, исключающим утечку.

## Самопроверка

- `tools/diagnose.py` — проверяет окружение и детектор; результат в `data/diagnose.log`.
- `tools/selftest_gui.py` — real-only GUI smoke check: окно запускается, действия демо отключены, входящая папка пуста.

Запуск: `.venv\Scripts\python.exe tools\selftest_gui.py`.

Для проверки готового дистрибутива используйте его real-only smoke check:

```powershell
$result = Start-Process -FilePath '.\dist\IntegrityGuard\IntegrityGuard.exe' -ArgumentList '--selftest-gui' -Wait -PassThru -WindowStyle Hidden
$result.ExitCode
```

Проверка использует временный пустой каталог данных; пакеты не создаются и не загружаются. Код 0 означает, что GUI
открылся, автоматический мониторинг видит пустую входящую папку, а демо-действия отсутствуют.

## Кодировка

Все текстовые файлы программы (исходный код, журнал событий, отчёты, манифесты, настройки) читаются и пишутся в UTF-8;

## Полнота обнаружения

Метрики отображаются только из независимой реальной выборки с подтверждённой разметкой
(`dataset_kind=real_independent`). Синтетические пакеты и сохранённые демо-показатели не загружаются.
Пока подходящая контрольная выборка не подключена, полнота обнаружения на реальных угрозах неизвестна.

Последний development-only эксперимент с добавлением уже использованных CTU captures 46/47 только в train завершился отрицательно: минимальная dev recall CI-L — 0,00288%; все dev FPR CI-U укладываются в 0,25%, но recall gate не выполнен. Этот checkpoint не внедрён; independent тесты не открывались. Подробности и SHA-256 — в [`docs/network-model-release-gate.md`](docs/network-model-release-gate.md).
