# Сетевая модель IntegrityGuard: выбранный pipeline

## Цель и ограничения

Сетевая модель ранжирует двунаправленные потоки по агрегированным признакам. Она не принимает решение о блокировке и не управляет Windows Firewall. Live-сокетные наблюдения и Pktmon-агрегаты не содержат достоверной истины о безопасности сами по себе.

## Источники разметки

Для текущего per-flow исследовательского кандидата используется CTU-13 с метками, опубликованными владельцами набора и сопоставленными по документированному правилу. В происхождении сохраняются URL, исходные SHA-256, версия схемы и исключённые неизвестные/фоновые метки. Метки модели или threat-intel не переносятся в ground truth.

Разбиение зафиксировано по целым захватам: 42–44 для обучения, 45 для валидации и выбора порога, 46–47 для независимого теста. Данные test нельзя использовать для обучения, ранней остановки, feature selection или настройки порога.

## Текущий встроенный кандидат

Checkpoint: `models/network_flow_v3_candidate.pt`. Его источник-метрики описаны в `models/network_flow_v3_candidate_metrics.json`, provenance — в `models/network_flow_v3_candidate_manifest.json`; приложение проверяет хеши при загрузке.

На объединённом независимом test (17 662 потока: 5 531 attack и 12 131 benign), при пороге 0,9999486, выбранном на validation capture 45:

- attack recall: 82,16%;
- benign false-positive rate: 0,0247%;
- attack precision: 99,93%.

По отдельным capture recall составляет 16,87% на 46 и 94,86% на 47. Такой разброс показывает ограниченный перенос даже между сценариями одного публичного семейства. Метрики описывают CTU-13, а не целевую сеть.

## Целевые сетевые данные

Реальные локальные наблюдения собираются отдельно и остаются без метки, пока независимые первичные свидетельства не связывают их с конкретным потоком. Подходящие источники: EDR/SIEM/IDS инцидент с временным интервалом и endpoint-связью, журнал сетевого устройства или подтверждённый перечень разрешённых сервисов. Любую метку сопровождают source ID, timestamp, схема соответствия, ссылка на evidence и SHA-256.

Неизвестные и фоновые потоки не принудительно превращаются в benign. Live-прогнозы не используются для обучения. Если достоверных меток целевой сети пока нет, допускаются только описательные результаты захвата и распределения score; показатели качества и release gate остаются незаполненными.

Для настоящей target-network оценки фиксируется отдельный захват после train/validation, сохраняется неизменяемый manifest и рассчитываются per-class support, recall, false-positive rate, precision, покрытие и интервалы неопределённости. Без успешной независимой проверки кандидат остаётся advisory-only, firewall enforcement выключен.

## Автоматизация

Во время работы приложения разрешены сбор разрешённых метаданных и построение рекомендаций. Автоматическое обучение допускается только на корпусе с provenance и независимыми целевыми метками; прогнозы из live-модели и неизвестные потоки в обучение не включаются.


Release-gate factors, target thresholds and the current completion ratio are documented in `docs/network-model-release-gate.md` and displayed in the application as a ten-stage progress bar. The bar is an equal-count engineering checklist; it is not model accuracy or training progress.
