# Направление интерфейса IntegrityGuard

Дата обзора: 11 ноября 2026 г. Референсы изучены по официальной документации
поставщиков, а не по рекламным заявлениям о точности детектирования.

## Что взять из существующих SOC-консолей

| Продукт | Полезный паттерн | Чего не переносить в IntegrityGuard |
|---|---|---|
| Wazuh | Разделение рабочих областей: события, целостность файлов, уязвимости, инвентарь; навигация связывает сводки с данными | Широкую поверхность enterprise-функций, которой в локальном приложении пока нет |
| Elastic Security | Обзор по времени, очереди оповещений и делам, переход из графика прямо к расследованию и контексту | Плотные аналитические панели и сложные настройки визуализаций для первого запуска |
| Microsoft Defender | Главная сводка с активными инцидентами и карточками-ссылками на подробности; понятная очередь и страница инцидента | Зависимость интерфейса от большого облачного набора продуктов и ролей |

## Выбранный баланс

- Стартовая страница — «Мониторинг»: сначала видны состояние очереди, вердикты и
  последние события; для проверки конкретного пакета остаётся отдельный экран.
- Постоянная боковая навигация сгруппирована по работе, управлению эталонами,
  качеству модели и настройкам.
- Тёмная нейтральная палитра использует один синий акцент. Зелёный, янтарный и
  красный оставлены для статусов, поэтому они сохраняют смысл.
- Сводные показатели перестраиваются в три колонки и не обрезаются на узком
  окне. Таблицы и подробности остаются читаемыми, а длинные страницы прокручиваются
  вертикально.
- Важные числа кликабельны или ведут к списку/событию; необязательные настройки
  остаются внутри соответствующего раздела. Демонстрационные пакеты не нужны для
  заполнения главной страницы — пустое состояние объясняет, какие реальные данные
  будут показаны.
- Числовая оценка не рисуется, если она не рассчитывалась. Цвет статуса не
  интерпретируется как доказательство безопасности; детали проверки и основание
  вердикта остаются видимыми.
