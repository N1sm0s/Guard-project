# Независимая оценка и выпуск кандидата

Кандидат из `data/models/candidates/<candidate_id>/` не заменяет активную модель после обучения.
Оценка запускается на странице «Обучение и оценка» и сохраняет результат в `candidate.json`.
Итог `release_eligible` означает только, что пройдены заданные вычислимые критерии; автоматической
активации нет. Кнопка активации требует повторного прогона оценки, повторной проверки SHA-256
манифеста и данных оценки, родительской модели и checkpoint кандидата. Затем предыдущая модель
сохраняется в `data/models/release_backups/`, а замена выполняется атомарно. Состояние операции
пишется до замены: при следующем запуске программа завершает/отменяет незавершённую транзакцию по
хешу фактически установленного файла. Откат возможен только если активный файл всё ещё совпадает
с выпущенным кандидатом и резервная копия совпадает с исходной моделью.

## Формат набора независимой оценки

Рядом с `evaluation.json` размещается `samples.pt`. Загрузка выполняется через
`torch.load(..., weights_only=True)`. Манифест:

```json
{
  "format": "integrityguard-independent-evaluation-v1",
  "data_kind": "real",
  "independent": true,
  "candidate_id": "<candidate_id>",
  "reviewer": "<проверивший разметку специалист>",
  "collected_at": "2026-11-11T10:00:00+00:00",
  "source_refs": ["<URL или ID первичного источника>"],
  "attestation": "Независимо проверены происхождение пакетов и метки.",
  "samples_file": "samples.pt",
  "samples_sha256": "<SHA-256 samples.pt>",
  "sample_count": 300,
  "label_schema": "binary_v1"
}
```

Каждый элемент `samples.pt` содержит `_event_id`, `_fingerprint` (SHA-256 пакета), `_project_id`,
`_label_evidence`, тензоры `x`, `adj`, `layers`, `behav` и `y` (`0` — легитимный пакет, `1` —
подтверждённая угроза). Идентификаторы и отпечатки должны быть уникальными и не пересекаться с
обучающим набором кандидата. Хеш файла сверяется с манифестом.

Также запрещено пересечение `_project_id` с `training_project_ids` кандидата:
другая версия того же проекта не считается независимым проектом. Регистр
и разделители `-`, `_`, `.` нормализуются. Манифест кандидата должен содержать
`training_project_ids_complete: true` и непустую историю проектов. Старые
кандидаты без этих сведений не допускаются к оценке до восстановления
доказуемой истории или повторного обучения с полными метаданными.
Эта проверка относится к дообучению кандидата; независимость от первоначальной
выборки родительской модели требует отдельного подтверждения.

## Критерии выпуска

- не менее 200 легитимных и 100 угрожающих пакетов;
- нижняя 95% граница Wilson для полноты кандидата не ниже 0,80;
- верхняя 95% граница Wilson для FPR не выше 0,02;
- деградация recall относительно родительской модели не больше 0,02;
- рост FPR не больше 0,01;
- снижение ROC-AUC не больше 0,02.

Оценщик записывает обе модели и все проверки в манифест кандидата. Изменение родительской модели
после обучения отменяет оценку. Эти пороги — инженерный начальный профиль, который требует
валидации на достаточно большом проверенном реальном корпусе. Поля `independent`, reviewer и
attestation фиксируют заявленное происхождение, но сами по себе не являются криптографическим
доказательством достоверности разметки. Пока такой набор не предоставлен и не проверен, выпуск
остаётся недоступен.
