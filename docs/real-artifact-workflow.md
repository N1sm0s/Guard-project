# Работа с реальными Python wheel

Раздел демо-пакетов раньше позволял показывать элементы интерфейса и получать
примерный результат на заранее сгенерированных объектах. Такой поток исключён
из рабочего приложения: синтетические пакеты не создаются, не попадают в
эксплуатационный журнал и не используются для оценки качества.

Вместо него монитор принимает подлинные `.whl` из `data/incoming`. Wheel — ZIP-
архив установленного Python-дистрибутива. IntegrityGuard не устанавливает и не
импортирует его. Статическая проверка ограничивает число файлов и объём чтения,
проверяет ZIP CRC, метаданные `METADATA`, внутренние хеши/размеры `RECORD`, SHA-256
каждого файла, зависимости и часть признаков исходников. Для `.py`-файлов
просматривается ограниченный объём текста; бинарные расширения не исполняются.

## Поток доверия

1. Оператор получает настоящий wheel из принятого источника и проверяет
   происхождение и ожидаемый SHA-256 вне программы.
2. Явно закрепляет этот артефакт как baseline. Программа сохраняет его копию,
   SHA-256 состава, URL источника и ссылку/заметку с подтверждением происхождения.
3. Монитор автоматически проверяет поступающий wheel. Точное совпадение
   закреплённого SHA-256 при полном `RECORD` даёт `ALLOW`.
4. Новая версия сравнивается с эталоном того же проекта: показываются изменённые,
   добавленные и удалённые файлы. Новый или изменённый wheel получает `REVIEW` и
   уходит в соответствующую папку обработки; версия не принимается автоматически.
5. Событие сохраняется в `events.jsonl` и `evidence.sqlite`. Числовой балл модели
   для wheel не создаётся. `RECORD` является внутренней согласованностью архива,
   а не подписью издателя и не доказательством доброкачественности.

Результат `ALLOW` означает только точное совпадение с заранее доверенным
артефактом. Он не является общим заключением, что пакет безопасен. Результат
`REVIEW` не означает, что найдено вредоносное ПО. Источник и provenance-ссылка
сохраняются как указанные оператором значения и автоматически не проверяются.

## Командная строка

Для публичного PyPI wheel добавьте `--verify-pypi` к `baseline-wheel`.
Перед записью эталона программа сверит имя файла и SHA-256 с конкретным релизом
PyPI по HTTPS. При несовпадении, отозванном файле, ошибке сети или неполном
ответе регистрация прерывается. Передаются только имя и версия пакета.
Сохраняются время проверки, URL метаданных, SHA-256 ответа и артефакта.
Файл повторно хешируется после копирования в реестр.

Это подтверждение совпадения с файлом PyPI, не проверка подписи издателя и
не заключение о безопасности. Решение закрепить эталон остаётся явным.
Без флага сохраняется статус `operator_supplied`: источник указан оператором,
автоматическая проверка не выполнялась. Для старых эталонов статус
`not_recorded`. В событиях сведения доступны в `baseline_source_verification`.
API: https://docs.pypi.org/api/json/.

```powershell
python -m integrityguard baseline-wheel `
  --wheel <trusted-wheel.whl> `
  --registry <registry> `
  --source-url <project-or-artifact-url> `
  --provenance-ref <attestation-or-review-reference>

python -m integrityguard check-wheel `
  --wheel <candidate-wheel.whl> `
  --registry <registry> `
  --report <report.pdf>
```

Первую команду следует выполнять только после ручной проверки источника,
версии и SHA-256. В GUI те же правила применяются автоматически после помещения
wheel в настроенную входящую папку.

## Проверка на опубликованных артефактах

Реальный неизменённый пакет `packaging` 26.2 и его опубликованное обновление
26.3 были загружены с PyPI без установки или импорта. Локальные SHA-256 сверены
с PyPI JSON API. На 26.2 закреплён эталон; 26.3 автоматически направлен в
`REVIEW`. Зафиксировано 17 изменённых, 8 добавленных и 6 удалённых файлов,
событие появилось в JSONL и SQLite, оценка модели отсутствовала. Это проверяет
обработку настоящего обновления и аудитный конвейер; поскольку пара не является
подтверждённым инцидентом, она не измеряет обнаружение вредоносного ПО и не
подтверждает качество нейросети.

Источники артефактов и формата: [спецификация wheel от PyPA](https://packaging.python.org/en/latest/specifications/binary-distribution-format/),
[packaging 26.2 на PyPI](https://pypi.org/project/packaging/26.2/),
[packaging 26.3 на PyPI](https://pypi.org/project/packaging/26.3/).

## Регрессионная проверка интерфейса

Исправлен фильтр журнала: события `wheel_static` и `wheel_validation_error`
теперь показываются без числового балла, как и события отсутствующего эталона.
Они учитываются в счётчиках мониторинга, но не добавляют фиктивные точки на
график оценок нейросети.

Для двух настоящих wheel одного проекта (эталон и отличающееся обновление):

```powershell
F:\New\integrityguard\dist\IntegrityGuard\IntegrityGuard.exe --selftest-real-wheels <baseline.whl> <update.whl>
```

Проверка создаёт временный каталог настроек и реестра, закрепляет копию первого
артефакта только в нём и проверяет реальные результаты ALLOW/REVIEW в таблицах,
счётчиках, фильтре журнала, SQLite и индивидуальном/сводном PDF. Производственные
эталоны, настройки и модель не изменяются. Пакеты не устанавливаются и не
исполняются. Код выхода 0 означает успешное завершение; 1 — ошибку проверки.
Это проверка интерфейса и отчётности, а не качества распознавания угроз.
