# План разработки IntegrityGuard (с 23.11.2026)

Основа — [development-roadmap.md](development-roadmap.md). Этот план раскладывает
приоритеты P0–P3 на шаги с критериями готовности. P4 (LLM-помощник) удалён из
продукта, работ по нему нет.

Правила, которым подчиняется каждый шаг (из `AGENTS.md`):
- только реальные артефакты; синтетика не считается доказательством;
- роли данных (train/dev/независимый тест) назначаются до чтения меток;
- блокировка сетевым классификатором не включается без валидированного
  кандидата и отдельного решения;
- после сборки EXE приложение перезапускается и проверяется путь процесса.

## Критерии, которые не закрываются кодом

Эти пункты требуют реальных данных и вашей сети, и без них не объявляются
выполненными:
- подтверждённые локальные метки инцидентов (сейчас 0);
- нагрузочный тест P95 ≤100 мс на целевой нагрузке;
- численная оценка потерь пакетов сенсора (`pktmon status` отвечает «Отказано в доступе»);
- независимый тест на целевой сети.
