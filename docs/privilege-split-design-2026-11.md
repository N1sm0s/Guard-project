части нужно от пользователя (раздел «Открытый вопрос»).

## Статус реализации (23.11.2026)

- Выбран вариант UAC (запрос при каждом захвате).
- Сделано в коде: `integrityguard/pktmon_segment.py` (захват в файлы с манифестом, проверка SHA-256 до разбора, запуск помощника через UAC), `tools/pktmon_helper.py` (помощник), переключатель `pktmon_helper` в GUI (по умолчанию выключен). Тесты: `tests/test_pktmon_segment.py`, все тесты проходят.
- Не сделано: сборка помощника отдельным EXE для собранного приложения (в собранной версии переключатель пока не заработает); реальная проверка с запросом UAC на машине (нужно нажатие пользователя); включение переключателя по умолчанию.

## Что сейчас

`integrityguard/pktmon_capture.py::capture_header_segment` при каждом захвате:
1. проверяет `IsUserAnAdmin()`, без него возвращает `administrator_required`;
2. запускает и останавливает Pktmon (`start`, `stop`), читает `counters`;
3. конвертирует ETL в pcapng (`etl2pcap`) и разбирает его `aggregate_capture`.

Весь процесс приложения работает с правами администратора, включая разбор
файлов и интерфейс. Это лишняя поверхность: разбор сетевых данных и GUI не
требуют повышенных прав.

## Цель

Привилегии нужны только для пунктов 2 (запуск/остановка Pktmon и счётчики).
Всё остальное должно работать от обычного пользователя.

## Предлагаемое разделение

- **Привилегированный помощник** (`tools/pktmon_helper.py`, собирается отдельным EXE).
  Принимает одну команду: «захватить N секунд в каталог X». Выполняет
  `start` → ждёт → `counters` → `stop`, сохраняет ETL, pcapng (через `etl2pcap`)
  и JSON со счётчиками и SHA-256. Ничего больше не делает.
- **Основное приложение без повышения прав.** Запускает помощника только на
  захват, читает готовые файлы, проверяет их SHA-256, разбирает
  `aggregate_capture`, как сейчас. Интерфейс и разбор работают без администратора.

## Контракт обмена

- Вход помощника: только аргументы `--seconds`, `--out-dir`. Никаких путей
  кроме `--out-dir`, никаких команд Pktmon извне.
- `--seconds` ограничен (как `_CAPTURE_SECONDS_MAX`), `--out-dir` должен лежать
  внутри каталога данных приложения, без символических ссылок и reparse points.
- Выход: `segment.pcapng`, `counters.json`, `manifest.json` (SHA-256 обоих,
  время начала и конца, версия помощника). Основное приложение проверяет
  SHA-256 перед разбором; несовпадение — сегмент отвергается.
- Владелец сессии Pktmon: помощник сохраняет тот же маркер владельца, что
  и сейчас, чтобы не остановить чужую сессию.

## Угрозы и меры

| Угроза | Мера |
|---|---|
| Подмена файлов между помощником и приложением | SHA-256 в манифесте, проверка до разбора; каталог с ограниченными правами |
| Помощник запускает произвольную команду | Нет входа для команд; только фиксированный набор вызовов Pktmon |
| Путь вне каталога данных | Проверка `resolve()` и отсутствия reparse points |
| Чужая сессия Pktmon остановлена | Тот же маркер владельца; без маркера не останавливать |
| Повышение прав через основное приложение | Основное приложение не импортирует помощника и не запускает его с повышением сам — только по явному действию пользователя |

## Открытый вопрос (блокирует реализацию)

Как запускается помощник с правами администратора?
- **Запрос UAC при каждом захвате.** Просто и без постоянно работающих привилегий,
  но окно подтверждения каждые N секунд неудобно для непрерывного мониторинга.
- **Задача планировщика с наивысшими правами.** Удобно для непрерывного захвата,
  но это то же решение, что отменённый P2.4: постоянно работающий процесс с правами
  администратора, создаётся один раз.

Без выбора реализация не имеет смысла: от него зависит, нужен ли постоянный
привилегированный процесс.

## Шаги после решения

1. Вынести вызовы Pktmon в `tools/pktmon_helper.py`, покрыть тестами разбор аргументов
   и проверку путей (без реального Pktmon).
2. Ввести манифест и проверку SHA-256 в `pktmon_capture.py`; тесты на подмену файла.
3. Заменить внутренний вызов `_run` на запуск помощника; старый путь оставить
   только за флагом, который по умолчанию выключен, до проверки.
4. Проверка на реальной машине: захват с помощником, захват без администратора
   (должен давать `administrator_required` и не падать), отказ при подмене файла.
5. Сборка EXE для основного приложения и для помощника; перезапуск с проверкой пути процесса.
