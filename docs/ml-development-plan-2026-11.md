# План разработки и обучения сетевой нейросети (с 23.11.2026)

Этот план объединяет дорожную карту (P0), план обучения и лабораторный протокол. Цель: классификатор сетевых потоков, который проходит проверку переноса на независимые данные и не превышает допустимые ложные срабатывания. Пока этого нет: кандидаты исследовательские, блокировка выключена.

## 1. Текущее состояние (зафиксировано по регистрациям)

| Что | Результат | Где записано |
|---|---|---|
| CTU-13, LOCO по захватам | медианная полнота 75%, порог не переносится | release-gate, LOCO |
| Признаки портов | артефакт ОС и семейства, исключены из кандидатов | release-gate, абляция |
| Лаборатория, калибровка v3 | флуд 96%, сканирование 99,9% при FPR 0,34% на 298 потоках | release-gate, v3 |
| SSH-перебор | не распознаётся: AUC 0 с объёмными признаками, 0% полноты в обучении | release-gate, кандидат v1 |
| Нейросеть-кандидат v1 | FPR 2,0% (6/298), не годится | release-gate, кандидат v1 |

Главные причины отставания:
1. **Мало фона.** Калибровка 750 потоков, проверка 298. Для оценки FPR на уровне 0,25% нужно не менее 3 838 доброкачественных потоков при нуле ложных срабатываний.
2. **Признаки не описывают короткие неудачные соединения.** Объёмные признаки делают SSH-перебор безопасным на вид; без них он ранжируется (AUC 0,98), но порог его пропускает.
3. **Одна лаборатория, одна семья атак.** Нет независимого набора данных, поэтому переносимость не доказана.

## 2. Принципы (не обсуждаются)

- Синтетика не считается доказательством качества. Лабораторные атаки и фон — это реальный трафик, записанный на собственном стенде; они полезны для разработки, но не для заявлений о сети.
- Роли данных назначаются до обучения: обучение, калибровка порога, проверка, независимый тест. Проверка и тест не используются для выбора признаков, порога или архитектуры.
- Каждый эксперимент регистрируется до запуска (хеши шардов, скрипта, протокол).
- Результат research-only, пока не пройдены все условия выпуска (раздел 6). Приложение не загружает кандидатов, блокировка выключена.
- Новых атак и фона не генерируем под цель «пройти проверку».

Правило: проверочный фон не используется ни для обучения, ни для калибровки. Калибровочный фон не используется для обучения.

### 3.2. Что нужно собрать

- **Фон:** не менее 3 838 доброкачественных потоков для проверки FPR 0,25% при нуле ложных срабатываний; разнообразный (веб, SSH, UDP, ICMP, DNS-подобный). Лаборатория даёт это медленно, поэтому параллельно нужен публичный фон с метками издателя.
- **Атаки с короткими соединениями:** серии неудачных SSH-подключений разной длины и интервалов, сканирование с паузами.
- **Независимый набор:** публичный набор реального трафика, который не использовался ни в одном эксперименте. Кандидаты: CICIoT2023 (ссылку от CIC пока не получили), UNSW-NB15. Роль назначается до чтения меток.
- **Локальный фон вашей сети:** со временем, только при подтверждённой безопасности всех удалённых адресов. Без этого FPR для вашей сети не оценивается.

## 4. Признаки

Этап A (код, без обучения): добавить признаки, которые описывают неудачные соединения, и проверить их на лаборатории как диагностику:
- число попыток к одному порту и интервалы между ними за окно;
- доля соединений без данных (SYN и RST или короткий ответ);
- длительность короткой двусторонней сессии без полезной нагрузки;
- соотношение входящих и исходящих пакетов без учёта объёма.

Признаки считаются из захвата тем же кодом, что и в рабочем режиме (`network_packet_flows`), чтобы совпадали обучение и эксплуатация.

Этап B: признаки-кандидаты регистрируются как отдельная версия схемы (например, v12). Старые версии не меняются.

Критерий: AUC по SSH-перебору без объёмных признаков выше 0,9 на калибровочном фоне, при этом FPR на проверочном фоне не растёт по сравнению с v10.

## 5. Обучение и калибровка

1. **Базовая модель:** MLP как в LOCO (64 скрытых, class-balanced, 20 эпох, seed 1907). Сравнения между моделями — только на одинаковых шардах и протоколе.
2. **Сравнение архитектур** (только после шага 4B): градиентный бустинг на тех же признаках, MLP. Выбор — по калибровочному фону, не по проверочному.
3. **Порог:** 99,75-й перцентиль калибровочного фона. Порог фиксируется до проверки и не подбирается под результат.
4. **Перекрёстная проверка:** leave-one-attack-family-out (как в v2/v3) и по времени. Оценка — медиана и минимум по семьям.
5. **Баланс классов:** веса по классам; для редких семейств (SSH) — повторная выборка только в обучающей роли.

Критерии продвижения к проверке: полнота на каждой удержанной семье не ниже 80% при FPR на калибровочном фоне не выше 0,25%.

## 6. Условия выпуска (все обязательны)

1. Независимый набор данных (роль «тест», не использовался): полнота не ниже 80% (нижняя граница 95% Wilson) на каждом захвате; FPR верхняя граница 95% Wilson не выше 0,25% на каждом захвате (`release-gate`, раздел 4).
2. Фон не меньше 3 838 доброкачественных потоков для верхней границы FPR 0,25% при нуле ложных срабатываний; на каждом независимом захвате.
3. Кандидат проходит регистрацию, воспроизводимость (тот же результат от того же шарда и скрипта) и аудит признаков.
4. Измерена задержка инференса на целевой нагрузке (P95 ≤100 мс) и численная оценка потерь пакетов сенсора.
5. Подтверждённые локальные метки инцидентов из вашей сети (сейчас их 0). Без них выпуск невозможен: лаборатория и публичные наборы не заменяют данные вашей сети.
6. Решение о блокировке отдельное: даже после всех пунктов блокировка включается только по явному решению, с оценкой ложных блокировок в вашей сети.

## 8. Инфраструктура

- **Лаборатория:** `IG-Attacker`, `IG-Victim`, коммутатор `IG-Lab`, сбор через административный скрипт (`tools/lab/*_elevated.ps1`), журнал сценариев до старта, правила меток `make_label_rules.py`, загрузка `stream_ingest.py`.
- **Приложение:** захват по всем компонентам (`--comp all` при наличии лабораторных), сохранение сегментов в `pktmon-segments` с SHA-256. Известное ограничение: в собственных сегментах приложения трафик между виртуальными машинами пока не виден, причина не найдена; данные для обучения собираются административным скриптом.
- **Учёт:** каждый шард с манифестом (SHA-256 захвата, правило меток, счётчики по протоколам). Регистрации в `outputs/lab/registrations`, отчёты в `outputs/lab/*`, выводы в `docs/network-model-release-gate.md`.

## 9. Риски

- **Переносимость** может не появиться даже с хорошими признаками: тогда нужны данные другого стенда или реальный трафик сети заказчика.
- **Фон** — самое узкое место: без больших объёмов FPR не оценивается, а ложные срабатывания в вашей сети станут видны только на эксплуатации.
- **Лаборатория** даёт однотипные атаки; это риск переобучения на инструменты (`hping3`, `nmap`). Поэтому обязательна независимая проверка.
- **Права и безопасность:** сбор требует административных прав; все скрипты работают только в изолированной сети и с журналом.
