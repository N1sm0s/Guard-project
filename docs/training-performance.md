# Ускорение обучения

Проверка 12 ноября 2026: NVIDIA RTX 3080 Ti, 12 ГиБ VRAM; в `.venv`
установлен PyTorch 2.11.0+cu128, CUDA доступна. Portable EXE использует отдельную
CPU-only сборку PyTorch для уменьшения размера. GPU-зависимости в EXE не добавлены.

Дообучение кандидата поддерживает `auto`, `cpu`, `cuda`. Пример запуска
из корня проекта с уже установленным GPU-окружением:

```powershell
.venv\Scripts\python.exe -m integrityguard train-candidate --data-root F:\New\integrityguard\data --model F:\New\integrityguard\models\detector.pt --device cuda
```

По умолчанию обучение использует 4 CPU-потока PyTorch вместо прежнего одного.
Флаг `--cpu-threads 8` позволяет выбрать восемь; допустимое значение ограничено
числом логических процессоров. После обучения прежняя настройка восстанавливается,
в том числе при исключении. Оптимальный лимит ещё нужно измерить на реальных
данных: увеличение потоков не гарантирует ускорения маленькой модели.

Перед запуском нужно указать фактическую активную модель: путь в примере
не обязательно совпадает с текущим выбором в настройках приложения.
На GPU перемещаются модель, батч и метки; перед калибровкой и сохранением
модель возвращается на CPU. Устройство записывается в манифест кандидата.
Отсутствие CUDA при явном выборе `cuda` вызывает ошибку, а не скрытую замену
на CPU. `auto` использует CUDA, когда она доступна в данном интерпретаторе.

Это отдельный кандидат: активная модель не заменяется. Ограничения по данным,
независимая оценка и проверки выпуска сохраняются. AMP и уменьшение точности
пока не включены: сначала необходимо измерить влияние на реальных данных.

Старый `ref_val.pt` рядом с моделью автоматически не загружается: происхождение
таких файлов не подтверждено. В рабочем конвейере непроверенная `ref_val`
отклоняется. Без отдельной проверенной калибровочной выборки сохраняется порог
родительской модели, что явно фиксируется в манифесте кандидата.

При текущей проверке подтверждённых образцов было 0. Поэтому обучение и
замер ускорения не выполнялись. Проверены доступность CUDA, перенос настоящего
checkpoint на GPU и обратно, а также отказ от обучения при недостатке данных.
Синтетические пакеты или обучающие тензоры не создавались. Полный GPU backward
на реальной размеченной выборке ещё предстоит проверить.

## Запуск из интерфейса

Планировщик GUI запускает отдельный процесс. Для EXE в штатном каталоге
`dist/IntegrityGuard` используется `.venv/Scripts/python.exe` соответствующего
проекта и `tools/training_worker.py`, если они существуют. Рабочий каталог
процесса временный, Python запускается с `-I`, произвольные интерпретаторы из
PATH и входящих пакетов не ищутся. Это доверенный код установленного проекта:
права записи в его каталог должны быть ограничены оператором.

Без окружения проекта standalone EXE запускает собственный CPU-worker.
При ошибке выбранного окружения результат явно отклоняется; скрытого повтора
обучения другим движком нет. Таймаут процесса — один час. Результат передаётся
через отдельный JSON-файл, защищённый лимитом размера; служебные файлы удаляются.
Блокировка ОС не допускает два worker/CLI-обучения в одном каталоге данных
и снимается при выходе процесса. Рабочая модель не активируется автоматически.

Проверены обнаружение CUDA из CPU-окружения приложения, отказ при пустой
выборке, конфликт двух запусков и неизменность настройки потоков родителя.
Полное обучение остаётся непроверенным до поступления реальной разметки.
